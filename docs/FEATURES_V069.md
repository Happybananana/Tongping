# 同频 V0.6.9 · 轨迹交汇 / WHERE WE CROSS

## 正式实现

在 V0.6.8「沿途车站 → 旅途年鉴」下增加 `04 / WHERE WE CROSS · 轨迹交汇`。

- 选定同一好友圈内的一位好友，显示两人的历史公开足迹。
- 内置 Natural Earth 公共领域世界地理轮廓，支持拖动、放大、缩小与自动居中，**不需要地图 JS Key**。这是一张可交互的地理位置概览，不是街道级导航地图。
- 我的足迹使用薄荷绿，好友的足迹使用黄铜金；双方共同抵达的**同一个共享地点 ID** 显示醒目菱形交汇点。
- 点击地图站点或交汇卡，分别展示两人的**已公开**到访日期、评分、旅行感想；剧透感想默认收起。
- 地图连线仅表示具有明确先后顺序的到访记录；日期不确定的点不连线，不代表真实交通路线。
- 同一日到访只能标记「同日到访（不代表同行）」，不会擅自声称共同出游。
- 支持全部足迹 / 只看交汇、重新同步、定位全部。

## 分享与安全

**双向明确许可、默认关闭。** `travel_share_settings.enabled` 对新账号默认是 `false`；任何一方未开启，RPC 不返回双方足迹。

经 `public.get_travel_crossing_tracks(p_friend_id)` 安全数据库函数读取。函数检查：
1. 已认证、请求人和好友均在**同一个圈子**，且不能选择自己；
2. 双方的分享开关均处于开启状态；
3. 只返回 `visibility='circle'`、`status='done'`、`circle_id=当前圈子` 的历史旅行记录；
4. 仅包含 `place_latitude` / `place_longitude` 非空、GCJ-02 坐标的地点；
5. 与现有收藏表、游戏动画数据、私密记录相隔离；随时关闭分享即可让下一次查询返回空结果。

分享开关仅对**足迹交汇地图**开放额外的显示许可；原本已设为「圈内可见」的评分和感想在好友频道中仍可能被圈内成员看到。若想彻底取消圈内可见，请将对应车票改为「仅自己可见」。

不读取手机实时位置、不使用 GPS、不上传定位权限、不添加新的第三方地图服务、不公开给圈子外用户。数据库函数仅返回双方主动公开的旅行记录；跨圈子或未双向同意将得到空集。应用与数据库均不推测同行。

## 位置和坐标的适用范围

- 位置来自 V0.6.8 已保存的高德 GCJ-02 坐标；地图绘制时近似转为 WGS-84 坐标系以对齐本地地理轮廓。数据库原始坐标不被改写。
- 旧旅行地、手动录入和旧版高德搜索产生的无坐标地点 **不会自动获得虚构坐标，也不会出现在地图中**；对应车票仍保留在旅行年鉴。建议使用 V0.6.8 的「记录一段旅程」向导添加带坐标的高德 POI。
- 同名城市/景点不一定是同一个实际 POI，因此交汇判断按共享 catalog_items.id 精确匹配，避免误认。
- 地图仅提供大洲/国家级地理轮廓，不提供街道、步行/驾车路线、详细行政边界。

## SQL

独立提供的 `Tongpin_V0.6.9_SQL.sql` 已按顺序包含 V0.6.8 和 V0.6.9 两段可重复执行的增量迁移：前者增加旅行日期和坐标列，后者仅新建 `travel_share_settings` 与受控 RPC。不修改现有记录。建议上线前备份 Supabase。

## 回归验收

- [ ] 两人未开启分享：地图不显示好友数据
- [ ] 我开启而对方未开启：RPC 返回空列表
- [ ] 双方开启、各有公开且带坐标的旧旅行：两条轨迹可见
- [ ] 我与好友都去过相同共享地点：显示交汇菱形和双人记忆
- [ ] 仅名称相同但地点 ID 不同：**不**判定为交汇
- [ ] 任一记录改为私密或关闭分享：重新同步后不再出现在地图
- [ ] 不同圈用户 ID：RPC 返回空列表
- [ ] 有日期的足迹按能确定的时间先后连线；同年年份模糊不强行连线
- [ ] 仅有一天相同记录：显示同日，不声称同行
- [ ] 手机端可以选择好友、缩放拖动、点击交汇站；键盘可以操作所有按钮
- [ ] 动画/游戏、讨论、旅行年鉴、高德搜索不受影响

## 部署

1. 备份 Supabase；执行独立提供的 V0.6.9 合并 SQL（内含幂等 V0.6.8 基础字段迁移）。
2. 解压源码 ZIP，将文件按原目录结构上传到 GitHub `main` 根目录并覆盖同名文件；**不要只上传 ZIP 本身**。
3. 等待 Vercel 自动部署，确认版本显示 `0.6.9`。
4. 两个不同圈内账号分别开启分享，各自建立**带坐标、已去过、圈内可见**的旅行记录，进行双人验收。

新增模型测试可运行 `node --test src/travelCrossingModel.test.mjs`。实际多账号 RLS 验证需要在部署的 Supabase 中进行。
