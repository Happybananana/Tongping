# V0.6.2 · 批量导入连续搜索与高置信度自动匹配

## 改动

导入 .csv/.xlsx 后先匹配本圈共享作品库。对仍未匹配的有效、已勾选行，自动连续排队搜索，不再每 8 条要求点击一次「继续匹配」。

- 前端最多 2 个正在进行的搜索请求，启动请求间隔 ≥ 750 ms；单次搜索限时 14 秒。
- 不需要逐批确认；提供进度条、已搜索数量、失败数量、「暂停搜索 / 继续自动搜索」按钮。
- 用户关闭导入弹窗或选择另一个文件时，取消旧队列，不让旧结果写入新表格。
- 搜索出错只标记对应行，可单独重试，不影响后续行。
- 在实际导入前仍需一次最终用户确认；导入操作不在搜索完成时自动执行。

## 自动匹配规则

只对类别相同且符合以下任一条件的结果进行**自动预选**：

1. Bangumi ID 完全相同、没有与表格年份冲突的候选；或
2. 标题/别名标准化后完全相同、同名候选唯一；若表格填写年份，则候选年份必须存在并一致；同名不同版本若按年份可明确区分，也可以自动选定对应版本。

其他情况（相似名称、年份缺失或冲突、多个同名候选）会显示待审核候选，需用户明确选择。自动预选也能手动取消/更换。

**自动选定不等于自动写入**：用户仍需要点击最后的「确认导入」，并同意创建未在共享库中的条目；不覆盖已有个人记录。

## 使用步骤

我的录像柜 → 批量导入表格 → 上传 CSV / XLSX → 等待进度条完成 → 检查待审核行 → 确认导入。

自动搜索仅在网页打开期间运行，关闭页面会中断；它不是后台任务。300 行的导入可能耗时较长，取决于网络及上游 API。无需新的 Supabase SQL 或 Vercel 环境变量。
