# 同频 V0.6.8 · 旅途年鉴 / JOURNEY ARCHIVE

## 当前版本实现

页面顺序：铁路头图 → 我的旅行年鉴 → 下一站想去 → 原有高德/圈内地点搜索 → 原有站台人气榜。
旅行记录使用独立的专属表单，并保留旧记录原样。旧版共享 `experiences` 表继续保存状态、分数、感想、可见范围。

### 个人旅行表单

- 「已去过」可保存评分（0.5–10，步长 0.1）、感想、日期精度（未知/年/月/日）以及可见范围。
- 「想去」不储存评分与到访日期，可以记录想去的理由。
- 默认仅自己可见；只有主动改成圈内可见的记录才参与原好友评价。
- 「记录一段旅程」搜索本圈共享地点，也可以使用新的高德坐标搜索或手动创建地点。
- 原有高德搜索和好友排行榜没有被替换；新搜索端点为 `/api/travel-places`，复用已有 `AMAP_WEB_KEY`。
- 已有同名地点不能仅凭名称推断为同一高德地点；优先用稳定的高德 POI ID。

### 旧记录与迁移

先执行 `supabase/migration_v068.sql`。给 experiences 增加 `visited_on` 和 `visit_date_precision`，给 catalog_items 增加 `place_latitude` / `place_longitude` / `place_coordinate_system`；全部允许 NULL，旧记录无损保留。
记得年份的旅行仅展示年份，记得年月的仅展示年月，不展示虚构的日。`updated_at` 不作为到访日期排序。
新加入的高德地点使用 GCJ-02 坐标；既有的地点不会自动得到虚构坐标。未配置地图 JS API，不展示真实地图。

### 数据备份与隐私

旅行页新增专门的「导出旅行档案 JSON」和「恢复旅行档案 JSON」，可保留日期与坐标；恢复时使用私密权限，跳过已有个人记录。
**注意：旧版主站顶部/账户区的通用 JSON 备份仍是旧格式，不包含旅行日期。** 为避免丢失新字段，请使用旅行页专门导出的 JSON 备份旅行日期；后续版本可再统一全站备份。
没有开放实时定位、好友足迹地图，也没有新增读取其他用户私人记录的权限。

### 完成度与规划

V0.6.8 为旅行档案 MVP。地图、交汇点、好友足迹可见性授权、同地多次到访保留给 V0.6.9。此版本不自动推断两个人同行。
