# 同频 V0.6.10 · 2～4 人轨迹交汇

## 版本与适用范围

**仅适用于已经安装了 V0.6.9 双人版的仓库**。
本版本是前端增量升级，不增加 Supabase 字段、RLS 策略或数据库 RPC；无需 SQL。
若仍在 V0.6.8 或更早版本，应先完成 V0.6.9 的数据库迁移与源码升级。

## 功能

- 登录用户始终作为第一个参与者；最多再选 3 名好友，总人数 2～4。
- 每位好友使用固定区别色，人物选择变更时重新调用当前的受控 RPC。
- 各成员分别通过 `get_travel_crossing_tracks(p_friend_id)` 进行授权校验；客户端只汇总已经允许返回的行。
- 根据同一个 `catalog_items.id` 聚合到访者，不合并相似名称。
- 可筛选「全部足迹 / 至少 2 人 / 至少 3 人 / 全员 n 人（n 为当前所选人数）」；显示每站实际到访人数。
- 点击站点显示最多 4 张公开回忆卡：时间、个人评分、文字感想。
- 日期不精确的地点不任意推断行程先后；同日到访不等于同行。
- 不发送 GPS/实时位置；旅行坐标来自 V0.6.8 已保存的高德地点数据。

## 安全与兼容性

- V0.6.9 RPC 在数据库侧强制校验当前用户和好友的同圈成员关系及**双向分享许可**。
- 必须是圈内可见、已去过、有有效坐标的个人记录，才会由 RPC 返回。
- 不读取私人记录，不支持跨圈查询，也不授予新权限。
- 好友关闭分享后，用户重新同步时不再展示其足迹。
- 旧车票和分享设置原样保留，`AMAP_WEB_KEY` 不变。
- 地图使用本地世界轮廓图而非实时路线规划。

## 验收

1. 右上角版本更新为 `0.6.10`，沿途车站旅行年鉴、高德搜索正常。
2. 已配置 V0.6.9 SQL 的情况下，无需执行新 SQL。
3. 一次可选 1、2、3 位好友，无法选第 4 位好友。
4. 2/3/4 人交汇计数正确；只选 2 人时不会出现“四人交汇”筛选。
5. 同 ID 到访地点计数正确；同名不同地点不应合并。
6. 私密/未到访/无坐标记录不可见；撤销分享后重新同步，不再显示足迹。
7. 移动端可以多选好友、缩放地图、点击交汇点和阅读回忆卡。
