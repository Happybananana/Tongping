# 同频 V0.6.11 · 我的旅行轨迹 / MY JOURNEY MAP

## 升级基础

在现有 **V0.6.10（四人交汇版）** 基础上增量升级。
仅替换同路径源码，无新增 Supabase 表/字段、RPC、环境变量或权限策略。**不需要执行 SQL。**

## 页面体验

「沿途车站」的地图区域新增双模式切换：

1. **我的旅行轨迹（默认）**
   - 只读取当前登录用户自己的 `experiences` 旅行车票，查询带有 `user_id = auth.uid()` 的用户过滤，并继续受 Supabase RLS 保护。
   - 「已去过」才产生个人地图足迹；「想去」留在愿望清单。
   - 个人模式显示本人公开和私密记录，不要求开启好友分享，也不会对好友公开私密记录。
   - 已到访、具备可靠 `GCJ-02` 坐标的地点显示为地图标记；点击可翻阅日期、评分、感想和可见范围。
   - 可推断严格时间先后关系的两站之间以虚线连接；没有日期、日期范围重叠或横跨国际日期变更线的地点不强制连线。
   - 缺少坐标的历史车票仍保留在年鉴；地图说明有多少条未定位，不以名称推算经纬度。
   - 地图提供拖动、缩放和「定位全部」操作。
2. **好友轨迹交汇（保留）**
   - 仍为自己 + 最多 3 位好友，总人数不超过 4。
   - 继续调用现有数据库 `get_travel_crossing_tracks` RPC，并坚持双方主动分享、圈内公开、已到访且有坐标才返回记录。
   - 保留交汇点、2/3/4 人筛选与多张回忆卡。

对旅行车票的新增、删除或恢复将通知正在打开的单人地图刷新。原高德搜索、游戏/动画收藏、旅行年鉴和完整备份入口保持不变。

## 数据保护

- **不新增 SQL**，沿用已部署 V0.6.8/0.6.9 的日期、坐标字段及权限。
- 个人地图仅查询自己的 `experiences`；不会为了画单人轨迹调用好友公开数据 RPC，也无需开启足迹分享开关。
- 从个人模式切换为好友模式时，前端先清空个人数据并替换地图视图；好友模式只显示数据库允许返回的共享足迹。
- 轨迹线是历史地点顺序示意，并非用户真实出行路线或实时定位。

## 验收建议

- 关闭好友分享开关，个人地图仍可以看到自己的已到访站点与私密回忆。
- 切到好友模式时，私密旅行车票不出现在好友交汇数据中。
- 两个具有明确先后日期的地点之间出现虚线；日期重叠或未知时不连线。
- 旧车票没有坐标时不会误显示在地图上，但仍可从旅行年鉴打开。
- 修改或删除个人旅行车票后，个人地图应同步更新。
- 手机端可切换模式，地图不应产生横向溢出。

此补丁包含独立的个人地图模型测试。真实 Supabase 账号、复杂历史记录及部署行为仍应在生产环境验收。
