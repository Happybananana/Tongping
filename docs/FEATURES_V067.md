# 同频 V0.6.7 · 海报墙评分牌分级与 0.1 分精度

## 范围
仅强化「我的录像柜 → 海报墙」评分牌，不改变海报位置、尺寸、卡片内容和共享评分算法。
游戏与动画统一使用六档评分牌：

| 评分范围 | 色系 | 评分牌 |
| --- | --- | --- |
| 0.5 ≤ x < 7.0 | 珊瑚红 | 标准牌 |
| 7.0 ≤ x < 8.0 | 明黄色 | 标准牌 |
| 8.0 ≤ x < 8.5 | 薄荷绿 | 浅底深字 |
| 8.5 ≤ x < 9.0 | 鲜绿色 | 亮底深字 |
| 9.0 ≤ x < 9.5 | 翠绿色 | 深底白字 |
| 9.5 ≤ x ≤ 10.0 | 深翡翠绿 | 深底白字、双内框及菱形标记 |

**边界精确按值划分，不先四舍五入再分类**；显示统一保留 1 位小数。
0 分仍不允许提交，与之前最低 0.5 的规则兼容。若以后决定开放 0 分，需另行改动校验和 SQL。

## 同步修正：支持任意一位小数
- 个人编辑评分改成步长 0.1。
- 个人评分保存和 JSON 历史恢复接受 0.5–10.0 的一位小数。
- Excel/CSV 批量导入接受 7.6、8.3、9.7；非法两位小数仍报错。
- SQL 通过 `supabase/migration_v067.sql` 放宽 experiences.rating 的旧检查约束；
  仍是 numeric(3,1)，既有评分值保留。
- Excel/CSV 导出格式无须改变，原本已支持一位小数。

## 部署顺序
1. 在 Supabase SQL Editor 先执行 `supabase/migration_v067.sql`（此前 SQL 迁移应已完成）。
2. 将 V0.6.7 改动文件覆盖现有 GitHub 仓库相同路径，保留 Vercel 环境变量。
3. 运行 `npm run test:features && npm run test:search && npm run build`。
4. 上线后分别验收 6.9 / 7.0 / 7.9 / 8.0 / 8.4 / 8.5 / 8.9 / 9.0 / 9.4 / 9.5 / 10.0 的颜色。
5. 用两位小数（例如 8.35）测试前端拒绝，并验证 7.6 可以保存、刷新、导入和导出。

## 兼容与安全
无新的环境变量。未修改 RLS、圈内共享权限、圈内排名算法或第三方平台评分。
这份说明仅是代码变更计划，真实 Supabase 联调需要在你的部署环境验收。
