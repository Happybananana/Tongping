# 同频 V0.5.6 — 找片优先与评分错绑修复

此版本在 **V0.5.5（无 Steam 搜索）** 之上修改。保留原有 VIDEO CLUB、铁路旅行子频道、Supabase、Bangumi/Jikan/IGDB/RAWG 搜索与封面代理。

## 修复

### 1. 手机底部导航由 6 项减至 5 项

保留「店内放映 / 找片 / 好友频道 / 沿途车站 / 我的录像柜」，移除中间的悬浮「＋ 新录入」。顶部「＋ 录入新体验」、首页「＋ 录入新体验」以及「我的录像柜」添加记录入口，调整为直接进入「找片」。

在「找片」页面先寻找现有馆藏或在线搜索结果，确实搜不到时才使用「手动建档」创建条目。旅行地点继续在「沿途车站」处理。

### 2. 「加入并评分」与当前作品严格绑定

根因：原代码在 `createCatalogItem()` 插入成功后仍等待完整 `refreshAll()`，随后 `recordForm(id)` 只从 `data.items` 查找；如果列表当时缺少新作品，`recordForm` 会静默选择游戏分类中的第一个条目（通常为《艾尔登法环》）。

新实现：

- `createCatalogItem` 在 Supabase 返回新条目后**立即**将其合并进当前馆藏状态，不等待再次全表查询；保存评分后继续执行完整同步。
- 搜索结果已有的元信息可直接创建条目，不再为获取 Bangumi 详情额外串行阻塞评分弹窗。
- `recordForm(id)` 必须找到准确作品才能打开；查不到时提示错误，不再自动选第一项。
- 评分弹窗顶部明确展示当前锁定作品的封面、分类、标题；表单使用固定、隐藏的 `itemId`，避免误切换作品而记录到别的条目。
- 导入过程中按钮会显示“正在加入片库…”并禁用，防止重复点击。

## 升级

将 ZIP 解压至 GitHub 仓库根目录，按原路径覆盖 `src/main.js`、`src/v056-flow.css`、`index.html`、`package.json` 等文件。**不用重建数据库、不需运行 SQL，也无需改动 Vercel 环境变量**。

仅需少量覆盖时使用 `v0.5.6-patch.zip`；如果当前仓库是 V0.5.5 则完整包和补丁都可以。

## 测试范围

- 原有 Node.js 自动化测试：**52 项通过**。
- 浏览器模拟验证：390px 手机底部仅剩五个入口，无页面横向溢出。
- 浏览器模拟导入全新游戏：`星际测试新片` → 弹窗显示该作品 → `input[name=itemId]` 保持新条目 ID，而非示例游戏 ID。
- 浏览器模拟已有动画：点击「葬送的芙莉莲」后，固定作品为已有动画 ID。
- 首页按钮确实跳转「找片」；旧表单不再静默回退到第一条游戏。
- 本环境尚无 Vite 本地依赖，`npm run build` 提示 `vite: not found`；需要 Vercel 正式构建及真实 Supabase 写入联调后方可确认生产环境。

预览文件使用独立模拟数据，不会连接真实 Supabase 或保存评分。**不要将模拟预览 HTML 取代 GitHub 里的 `index.html`。**
