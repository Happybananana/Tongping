# 同频 V0.6.5 · 批量审核与空条目安全清理

基于 V0.6.4；继续保留 VIDEO CLUB / COLLECTION 双主题、找片、评分、帖子、海报墙、旅行等原有功能。不接入 Steam 搜索。

## 本次变更

### A. 批量搜索限速调整
- 同一批量导入中，两个 worker 共用一条启动节拍：**每隔 2400ms** 启动一个请求（约每分钟 25 次，包含重试），后端暖实例原有限流为每分钟 30 次。
- 保留 `Retry-After` 全队列冷却、最多 3 次自动重试、超时和临时故障区分。
- 如果其他标签页/设备使用同一账号搜索，仍可能触发 429；前端会自动减速重试。
- 300 个完全不同的联网搜索，单按启动节拍估算约 12 分钟，实际还取决于上游响应、网络和重试。

### B. 集中审核表格
- 上传 Excel / CSV 后有三个筛选：**全部**、**只看待审核**、**无结果 / 失败**。
- 待审核 = 网络检索得到候选、但尚未明确选定的项目；选择候选后立即从该过滤视图消失。
- 所有自动搜索结束后，行顺序按「待审核 → 已匹配 → 无结果或失败 → 无效行」调整。搜索中不强制改变可见行位置，避免误点。
- 原有安全规则保持：共享库精确匹配、高置信自动匹配、人工确认结果默认勾选；未审核、没结果与失败默认不勾选。

### C. 删除无关联记录的共享作品
- 作品详情页对**条目创建者**增加「删除空条目」。其他用户及官方/示例公共条目不会显示。
- **必须先执行 `supabase/migration_v065.sql`**，否则数据库不存在删除 RPC，按钮无法使用。
- 数据库事务内再检查：用户已登录、创建者本人、当前圈子成员、条目属于该圈子。
- 数据库会查所有 `experiences`（含别人的**私密记录**及未评分收藏），以及 `circle_posts`：只要存在任意关联就拒绝删除。
- 这是有意**比「无评分即可删除」更严格**的安全限制，因为不能无提示地连带删除其他成员未评分的收藏或者已有帖子。要删除旧的空条目，应先清理自己的个人记录；其他成员的隐私记录无法由创建者擅自移除。
- 使用带父表行锁的安全数据库函数，防止客户端通过直接删除绕过校验或并发插入造成关联数据丢失。

## 部署流程（从 V0.6.4 升级）

1. 备份当前 GitHub 仓库版本。
2. 确认已有 V0.5.7 的帖子迁移；进入当前 Supabase SQL Editor 执行 **`supabase/migration_v065.sql`**。它不会删除旧数据，可重复执行。
3. 上传升级补丁内的对应文件至 GitHub 仓库，覆盖现有文件。Vercel 将自动重新构建；不需要新增环境变量。
4. 在「我的收藏 → 批量导入」测试筛选按钮。在「找片」中创建一个**没有任何个人记录/帖子**的测试条目，进入详情页测试删除。再确认带评分/收藏的条目无法删除。

**不要重新运行 `supabase/schema.sql`**，该文件面向全新项目初始化。
