# 同频 V0.5.4 · 手机版布局与多来源图片修复

本版从 **V0.5.3-r1** 升级，不修改 Supabase 数据结构或原来的评分记录。

## 本次修复

- 移动端首页「朋友正在播放」：修复末尾 CSS 的双列覆盖，320–430px 手机强制使用单列完整卡片。
- 修复四张 Supabase 初始动画封面：旧版 `https://api.bgm.tv/v0/subjects/{id}/image?type=large` 自动改为同域 `/api/cover?subject={id}`。服务端处理受限跳转和图片大小；针对四张已知封面可在 Bangumi 失联时尝试经过核对的 Jikan/MAL 封面。
- Jikan（非官方 MAL 只读 API）：**仅在 Bangumi 动画搜索失败或无结果时**尝试备用。中文搜索不保证命中，建议也用日文/英文名称。
- RAWG 游戏资料：可选备用，需开发者申请 `RAWG_API_KEY`，并遵守官方来源署名/链接和额度规则。IGDB 保持原样。
- 增加受限同域图片代理 `/api/media`，仅允许已知图床和图片路径（MAL、RAWG、IGDB、Steam 公开封面）；阻止开放代理、重定向与过大图片。
- MAL 与 RAWG 搜索结果显示各自来源评分，不冒充 Bangumi 评分，不计入圈子榜单；本版未增加独立持久化 MAL/RAWG 评分字段。

## 上传部署

1. 将升级补丁的文件按原路径上传/覆盖你的 GitHub 仓库，或解压完整包将项目内容上传到仓库根目录。
2. 通过 Vercel 自动部署；无需运行 SQL。
3. 浏览器访问 `https://app.1t4.online` 检查：手机首页动态单列；四部默认动画封面；搜索备用来源。
4. **无需修改环境变量即可使用 Jikan 兜底**。但 RAWG 需要在 Vercel Environment Variables 中配置 `RAWG_API_KEY`，不要写入前端 `VITE_` 变量。
5. 默认仍只走 Bangumi 官方图片主机；Bangumi 及 Jikan 同时不可达时显示本地风格化占位封面。镜像 `BANGUMI_COVER_MIRROR` 默认关闭，不自动将请求发送给未知社区镜像。

## 注意事项

- 中国大陆的实际跨境连通性取决于网络、Cloudflare/Vercel 路由和第三方服务，没有一个公开海外数据源能保证永久稳定；服务端代理主要解决客户端直连问题。
- 原有四张动画封面数据**不必重建、也不要执行旧版 `schema.sql`**，新前端自动兼容。
- Jikan 是基于 MyAnimeList 的非官方服务，受限流（公开文档为 3 次/秒、60 次/分钟），使用时应避免高频刷新。
- RAWG 游戏资料按其现行 API 条款要求署名与链接；不要将 RAWG Key 提交 GitHub。
- 封面代理只处理图床白名单中的图片，其他网站的私人/自定义图链可能仍在用户浏览器直连。

## 验证

本版 49 项 Node.js 自动化测试通过，并使用 Chromium 在 320、360、375、390、430px 等视口验证了手机动态卡片单列及横向溢出情况。
由于当前环境缺少 Vite/npm 依赖且没有接入你的生产 Supabase，**完整生产构建与实际第三方网络联调仍未完成**。请在 Vercel 构建通过后，再用国内手机网络检查真实封面。
